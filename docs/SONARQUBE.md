## Setup

1. Select GitHub Actions as the analysis method in the Sonar project. Disable
   Automatic Analysis if enabled, so that it does not compete with CI analysis.
2. Create a Sonar token authorized to analyze this project and save it as the
   repository Actions secret `SONAR_TOKEN`. Never commit or paste the token into
   an issue, PR, log, or documentation.
3. Analyze PRs through the workflow. Pushes to `main` will establish and update
   its baseline after the workflow is merged. The first PR analysis succeeded
   even though this project had no prior `main` analysis.

The workflow analyzes pushes to `main`, same-repository PRs and manual runs.
It imports a Clippy JSON report and waits up to 300 seconds for the Quality Gate.
A missing token fails explicitly; a successful upload is not a passed gate.
Fork and Dependabot PRs are skipped because repository Actions secrets are not
available to those events. A skipped job is not evidence of a passed Sonar gate.

No coverage report is generated by this initial integration. Unit-test counts
are not coverage, and no coverage threshold has been lowered or disabled.
Real PipeWire validation remains a separate requirement before merge.
